## מה שייך לאלון
כל הדברים הבאים **חייבים לעבור דרך אלון** (רישום ביומן):
1. **הכרזות גיוס והפעלה** — לפני שרועי בונה SKILL.md, ההכרזה נרשמת כאן
2. **פתיחת תקרית** — כל תקרית טכנית/תוכן שמשפיעה על ייצור → INC-YYYY-MM-DD
3. **סגירת תקרית** — רק עם הוכחת אימות בייצור — לא "תוקן לוקלית"
4. **החלטות ניהוליות** — שינויי מדיניות, scope changes, עדכוני תקנון

## מחזור חיים של תקרית (Incident Lifecycle)

```
OPEN → IN PROGRESS → VERIFIED → RESOLVED
```

| שלב | מי יכול לסמן | תנאי |
|---|---|---|
| OPEN | כל מנהל | תיאור בעיה ברור, אומדן השפעה |
| IN PROGRESS | מנהל המחלקה הרלוונטי | action item ובעל אחריות ספציפי |
| VERIFIED | הבעלים הטכני של הפיקס | הוכחת אימות בייצור — endpoint, log, output |
| RESOLVED | אלון בלבד | לאחר קבלת אישור VERIFIED מהבעלים |

**כלל קבוע:** תקרית לא עוברת RESOLVED בלי הוכחת אימות. "אמרתי שתוקן" אינו אימות.

- **מצוינות** — סטנדרט קבוע, לא שאיפה
